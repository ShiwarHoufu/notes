# journalctl

`journalctl` 是 **systemd 自带的日志查看工具**。
systemd 把系统、内核、服务、程序的日志统一存在一个二进制日志库（journal）里。

- `-b`：按启动批次筛选日志
    - `-b 0`：**当前这次开机**的日志（默认）
    - `-b -1`：**上一次开机（上次重启之前）**的日志，你查宕机 / 重启前的日志就是用这个
    - `-b -2`：上上一次开机
- `-k`：只看 **kernel 内核日志**，网卡、磁盘、OOM、内核 panic、硬件相关报错都在这里
- `--no-pager`：不进入分页（less），一次性全部输出，方便管道给 grep /tail 过滤

其他高频常用参数：
- `-u xxx.service`：只看某个 systemd 服务日志，比如 `journalctl -u docker`
- `-f`：实时跟踪日志
- `--since "2026-10-22 08:00:00"  --until ""`：按时间筛选
- `-p err`：只看 error 级别以上的错误日志


# atop

atop 是 Linux 上的**高级系统 & 进程监控工具**（Advanced System & Process Monitor）。
核心亮点是：它既可以**实时**看负载，又会持续记录**每个进程的资源历史快照**，支持事后回放。

**和 top /sysstat（sar）的关键区别**：
1. **top / htop**：只看**实时**状态，宕机、凌晨出问题之后，没有历史录像，事后查不到；
2. **sysstat（sar）**：只存**系统级别**统计（整机 CPU、整机磁盘），**分不清是哪个进程**干的；
3. **atop**：定时把**每个进程**的 CPU、内存、磁盘 IO、网络 IO 快照写到日志文件（`/var/log/atop/`，按天归档），出问题之后可以随时回放，回溯当时每个进程的资源占用。
