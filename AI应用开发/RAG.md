**Retrieval-Augmented Generation，检索增强生成**

解决的问题：**幻觉**
- LLM 训练数据有时间截止点，且企业内部资料不在模型训练集里。所以模型容易编造不存在的事实、数据。

# 过程

![[IMG_20261024_145843.jpg]]
## 阶段 1：离线建库

1. **文档加载**：PDF、Markdown、Word 等原始文档；
2. **切片**：把长文档切成短片段（chunk）；
3. **Embedding（向量化）**：用**向量模型**把文本转成向量，捕捉语义含义；
4. **存入向量数据库**：建立索引，支持快速语义相似度检索。

**ETL（Extract, Transform, Load）**：
- Extract：从文档、数据库等原始来源读取数据
- Transform：清洗、切分、向量化等处理
- Load：存入向量数据库

## 阶段 2：检索 + 生成

1. 用户提问，把问题也转成向量；
2. 在向量库检索，召回语义最相近的 Top-K 文本片段；
3. 把用户问题 + 检索出来的片段一起塞进 Prompt 给 LLM；
4. LLM 参考材料输出回答。

# 向量数据库
## Point（向量点）

Point 是**向量数据库里最小存储单元**，等价于关系库 Table 里的一行记录（Qdrant、Milvus、Chroma 都用这个概念）。 
> 它之所以叫 point：**embedding 向量就是高维空间里的一个点**。

一个 Point 固定由三部分组成：
1. **id**：唯一标识（UUID），用来定位、更新、删除。
2. **vector**：embedding 向量，**浮点数数组，相似度计算的主体**
3. **payload（可选）**：JSON 格式元数据，原文、标题、时间等，用来做**过滤条件**和结果返回
