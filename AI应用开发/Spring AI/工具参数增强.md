
```java
@Tool(description = "Get the current weather for a given location")  
public String weather(String location) {  
    return "The current weather in " + location + " is sunny with a temperature of 25°C.";  
}
```
我们在定义 Tool 的时候，可以设置参数（比如这里的`location`）。然后大模型在调用工具的时候就会自动去填这个字段，包含在返回的 **ToolCalls** 里面：

但是除了这些工具内部需要的**业务参数**，如果我们开发者还想拿到模型的**推理过程、置信度**等信息，该怎么做？
>就是向大模型要求：“调用工具的时候，顺带写下你为什么要调用这个工具，以及你有多大把握”。

可能会想到：直接在定义 Tool 的时候加几个参数不就行了吗？
这样做从功能上完全可以，大模型照样会去填写这些参数。但是显然不优雅：

- 让每个工具都往自己的参数表里塞几个**跟业务无关**的字段，还需要手动忽略；
- N 个工具复制 N 份参数；
- 工具的作者怎么知道你要什么参数？

**Spring AI 2.0** 的 **Tool Argument Augmentation**（工具参数增强）提供了解决办法，让你可以
**不用修改原有工具的实现代码**，就能从大模型侧捕获额外信息。

## 额外参数

首先定义一个 Record 来说明你要为 工具Schema 追加的额外参数。比如：
```java
public record AgentThinking(  
       @ToolParam(description = "Your step-by-step reasoning for why you're calling this tool and what you expect",  required = true) String innerThought,  
  
       @ToolParam(description = "Confidence level (low, medium, high) in this tool choice",  required = false) String confidence,  
  
       @ToolParam(description = "Key insights to remember for future interactions",  required = true) List<String> memoryNotes) {  
}
```

原有工具的代码是没有变更的：
```java
static class MyTools {  
    @Tool(description = "Get the current weather for a given location")  
    public String weather(String location) {  
       return "The current weather in " + location + " is sunny with a temperature of 25°C.";  
    }  
}
```

## AugmentedToolCallbackProvider

把普通工具（或已有的 ToolCallbackProvider）包一层，往每个工具的 JSON schema     
里追加一组额外的输入字段。
```java
AugmentedToolCallbackProvider<AgentThinking> provider = AugmentedToolCallbackProvider  
    .<AgentThinking>builder()  
    .toolObject(new MyTools())  
    .argumentType(AgentThinking.class)  
    .argumentConsumer(event -> {  
       // 解析好的 AgentThinking
       AgentThinking thinking = event.arguments();  
  
       logger.info("LLM Reasoning: {}", thinking.innerThought());  
       logger.info("Confidence: {}", thinking.confidence());  
       logger.info("Thinking notest: {}", thinking.memoryNotes());    
       logger.info("Tool: {}", event.toolDefinition().name());  
    })  
  
    // 交给 Tool之前把额外参数删掉（这里Tool只需要 location）
    .removeExtraArgumentsAfterProcessing(true)  
    .build();
```
**argumentConsumer** 是构建 provider 时注册的回调函数：
每当 LLM 调用被增强的工具，Spring AI 就会把解析好的额外参数打包成你的 T 类型（这里就是 AgentThinking），并调用这个回调函数。

代码中 event 的类型其实是这个：（这里 T 为AgentThinking）
```java
public record AugmentedArgumentEvent<T>(
ToolDefinition toolDefinition,
String rawInput,
@Nullable T arguments) {
}
```
> AugmentedToolCallbackProvider 实现了 ToolCallbackProvider 接口，所以它能直接丢给 ChatClient.Builder.defaultTools()
