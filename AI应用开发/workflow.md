# Prompt Chain
![[Pasted image 20261020132617.png|611]]

**当任务能拆成固定顺序的子任务时**，用多个简单 LLM 调用代替一次复杂调用，获得更高的**准确率**
> 代价是调用耗时更长， token消费更高

应用场景：
- **多阶段内容生成**：先生成营销文案，再将文案翻译成其他语言
- **分步数据处理**：从报告中提取数值 -> 格式标准化 -> 排序 -> ...
- **阶段性校验的任务**

# Routing
![[Pasted image 20261020133444.png|577]]

对输入内容做分类，将其分发到专门的后续任务。适合处理**存在明确类别、且各类子任务适合分开处理**的复杂场景。
> 分类判断可以用大模型，或者传统机器学习分类模型

核心优势：
- **关注点分离**：分支可以针对特定类型的输入单独优化（避免出现优化 A 场景，B 场景效果变差）
- **提升准确率**：专用提示词各司其职，处理最擅长的任务
- **架构可扩展**：方便新增路由分支与专用处理器
- **资源利用率更高**：把简单任务分配给轻量模型

应用场景：
- **客服工单意图分流**：识别用户咨询类型（通用咨询、退款申请、故障报修），分发到专用分支
