# Q , K , V 的含义

输入的每个 token（词向量），分别乘 3 个可学习线性矩阵得到三个向量：

- **Q（Query 查询）**：当前 token 的**搜索意图** ——「我想找哪些上下文信息」
- **K（Key 键）**：每个 token 的**检索标签** ——「我具备什么特征，可以被别人搜到」
- **V（Value 值）**：每个 token 的**真实内容** ——「如果被选中，我提供什么信息」

# 两个阶段

- **Prefill**：一次性处理全部输入 prompt，算出所有 token 的 K、V，长 prompt 非常慢，这是首 token 等待时间（TTFT）的主要来源。
- **Decode**：大模型推理（生成 token）时，是逐 token 生成，每次只算新 token 的 Q，复用已经算好的 KV。
# KV Cache

 >LLM 大幅节省算力，加速的核心技术。

- **同一个请求内**，加速 Decode 阶段。
- 生命周期：单次对话，请求结束立刻释放显存。

# Prompt Cache

- **多个不同请求之间**，复用相同前缀，**跳过重复的Prefill**计算，降低首token延迟、减少计费
- 生命周期：跨请求保存在服务端显存 / 内存，LRU 淘汰
