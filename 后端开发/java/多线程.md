# 基础概念

**1. 并发与并行**
- 并发：多个指令在单核CPU上交替执行
- 并行：多个指令在多核CPU上同时执行

**2. 进程与线程**
- 进程（Process）：一个正在运行的程序实例。
- 线程（Thread）：进程里一条独立的执行流，CPU 调度的最小单位

# 实现多线程的方法

几种方法的本质：**new Thread () + 调用 start ()**

**start() 和 run() 的区别**：
- `start()`：申请**新线程**，自动调用 `run()`；
- `run()` 只是普通方法，不会开新线程。

## 1. 无返回值

有关源码如下：
```java
public class Thread implements Runnable {
    // 任务对象
    private Runnable target;

    // 构造方法：传入Runnable
    public Thread(Runnable target) {
        init(null, target, "Thread-" + nextThreadNum(), 0);
    }

    @Override
    public void run() {
        if (target != null) {
            target.run();
        }
    }
}
```

```java
@FunctionalInterface
public interface Runnable {
    public abstract void run();
}
```
**方式1：继承 Thread 类**：
	- 创建一个类继承Thread类，重写 run() 方法；
	- 实例化该子类对象，调用 start()方法

**方式2:  实现Runnable接口**
	- 创建一个类实现 Runnable 接口，并重写 run() 方法；
	- 实例化该实现类对象，传进 Thread 构造器

# 线程的生命周期

![[IMG_20261112_131803.jpg|591]]
### 1. NEW（新建）
- `new Thread()` 之后，还没调用 `start()`
- 仅仅在堆里创建了线程对象，**操作系统内核线程还没创建**
- 不能直接 `run()`，直接调用 `run()` 只是普通方法执行，不会开新线程

### 2. RUNNABLE（可运行）
调用 `start()` 之后进入这个状态。

> 这个状态包含**两层**：**READY(就绪) + RUNNING(正在 CPU 运行)**
> 
> **JVM** 没办法精准感知**操作系统层面**”READY ↔ RUNNING“这两个极快切换的子状态，所以把它们合并成 RUNNABLE。JVM 只关心：这个线程能不能被 CPU 调度。

### 3. BLOCKED（阻塞）

**只有一种场景：等待 `synchronized` 排他锁**
- 线程想去执行 `synchronized` 代码块 / 方法，但是锁被别的线程持有
- 锁释放后，它去竞争锁，抢到就进入 RUNNABLE

> 注意：`Lock.lock()` 阻塞**不是 BLOCKED，是 WAITING**

### 4. WAITING（无限等待）

线程主动挂起，**需要别的线程唤醒** 

进入方式：
- `Object.wait()`
- `Thread.join()`
- `LockSupport.park()`

唤醒方式：
- `Object.notify() / notifyAll()`
- 被 join 的线程执行完毕
- `LockSupport.unpark(thread)`

> 这个状态的线程不竞争锁

### 5. TIMED_WAITING（超时等待）

带超时时间的等待，时间到了自动唤醒，也可以提前唤醒

进入方式：
- `Object.wait(long timeout)`
- `Thread.sleep(long)`
- `Thread.join(long)`
- `LockSupport.parkNanos() / parkUntil()`

>**`sleep()` 不会释放锁；`wait()` 会释放锁**

### 6. TERMINATED（终止）

线程执行完毕 / 异常退出，生命周期结束
- run () 正常执行完
- run () 抛出未捕获异常终止
>终止后的线程**不能再次 start ()**
