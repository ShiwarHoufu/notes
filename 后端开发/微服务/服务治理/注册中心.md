# 远程调用

服务之间通过网络 HTTP 调用对方暴露出来的接口。

| 方案           | 底层                                     | 特点                                  | 适用场景                              |
| ------------ | -------------------------------------- | ----------------------------------- | --------------------------------- |
| OpenFeign    | HTTP + Ribbon/SpringCloud LoadBalancer | 声明式接口，像调用本地方法一样，代码简洁，SpringCloud 标配 | 业务同步调用，面试重点                       |
| RestTemplate | HTTP                                   | 原生，模板调用，手写 URL，代码繁琐                 | 简单临时调用，老项目                        |
| WebClient    | HTTP（Reactor 响应式）                      | 非阻塞、响应式，Spring5+                    | 高并发、响应式项目（SpringCloud Gateway 内部） |
| Dubbo        | TCP（RPC）                               | 二进制协议，性能高，自带序列化                     | 对性能要求高、内部服务密集调用                   |
>在微服务集群场景下，通常搭配**服务注册中心（Nacos/Eureka/Consul）**：服务提供者注册地址，消费者拉取实例列表。

# 注册中心

解决服务之间 “如何找到对方” 的问题，是微服务的地址通讯录 + 状态管理器。

## 2. 作用

1. 消除 IP、端口硬编码（解耦），给消费者**提供实例列表**，让消费者通过服务名称调用；
2. 服务启动自动注册、下线自动摘除，**自动剔除故障实例**，支持**动态扩缩容**；
3. **配合负载均衡算法**实现集群调用；
