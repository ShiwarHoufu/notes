
Spring Boot 自动配置，就是自动帮你创建 Bean、装配 Spring 容器，省去手写大量 XML 或者`@Bean`配置的过程。

## 一、通过 @Component 进行自动配置

启动类的注解：
**@SpringBootApplication** =
- @SpringBootConfiguration  
- @EnableAutoConfiguration  
- @ComponentScan 
	- 组件扫描，**默认扫描启动类所在包及其所有子包**；如果自定义，则默认的范围不会生效。
## 二、通过 @Import 进行自动配置

手动把指定类里的 Bean 注册到 Spring IOC 容器
> @ComponentScan是**扫描包** ；`@Import` 是**精准导入**

```java
@Import(xxx.class)
public class AppConfig {
}
```

它支持导入 3 种类型：
1. **导入 @Configuration 配置类** 把另一个配置类里所有`@Bean`全部加载进来
2. **导入普通类** 直接把这个类本身注册成 Bean。这个类本身不需要再加`@Component`。
3. **导入 ImportSelector 的实现类**
	- 自定义实现类，然后根据条件，动态返回需要导入的类名的**数组**：
```java
// 普通Bean，我们想把它导入容器 
class Cat { } 
class Dog { }

// 自定义ImportSelector实现类
public class MyImportSelector implements ImportSelector {
    @Override
    public String[] selectImports(AnnotationMetadata importingClassMetadata) {
        return new String[]{Cat.class.getName(), Dog.class.getName()};
    }
}
```

因为第三方依赖的提供者是最熟悉该依赖有哪些功能，需要进行什么自动配置，所以第三方依赖的提供者通常给使用者**提供一个开关注解**，使用者只需要加一个注解，便自动导入一大堆配置类。这样使用者就不需要自己去写`@import`了。
```java
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Import(MyImportSelector.class) 
public @interface EnableMyDemo {
}
```

 **`@EnableAutoConfiguration`的实现机制就是如此**：
 ```java
@Import(AutoConfigurationImportSelector.class)  
public @interface EnableAutoConfiguration {
}
 ```
 
- starter 自带的核心能力，大多自动装配，不用写`@Enable...`；
	这类组件，开发者会把配置类放进**AutoConfiguration.imports**，
	pom 引入即生效，不用注解
- 附加增强功能一般要 `@Enable...` 手动打开 (比如定时任务)

`AutoConfiguration.imports`中的配置类不是一定生效的，可能还有**条件判断**：
- **@ConditionalOnClass**：classpath 存在指定类才生效（比如引入 spring-web 才会加载 WebMvc 自动配置）
- **@ConditionalOnMissingBean**：容器里没有用户自己定义的 Bean，才创建 Bean
- **@ConditionalOnProperty**：配置文件满足条件才开启
