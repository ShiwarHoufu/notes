# 一、什么是消息队列

在不同程序 / 服务之间异步传递消息。
- **消息 Message**：要传输的数据（JSON、文本、二进制）
- **队列 Queue**：消息存放的地方，先进先出 FIFO（也有主题模式）
- **生产者 Producer**：把消息丢到队列里，丢完就可以去干别的，不用等对方立刻处理。
- **消费者 Consumer**：有空的时候，再从队列里取出消息处理。
- **Broker**：MQ 服务实例

# 二、核心作用

## 1. 解耦

![[IMG_20261012_101523.jpg|466]]
引入MQ之后，库存系统或物流系统挂了不会影响订单系统正常运行。

## 2. 异步提速
![[IMG_20261012_134545.jpg|527]]
不用同步等待结果，提升接口响应速度。 注册 → 立刻返回 “下单成功”，发短信、发邮件在后台慢慢处理。

## 3. 削峰填谷
![[IMG_20261012_134533.jpg|417]]
请求先进 MQ 排队，消费者按固定速度慢慢消费，挡住秒杀瞬间流量高峰，避免压垮数据库。

# 三、使用 MQ 的问题

1. **系统可用性降低**：引入的依赖越多，系统维护越复杂。（不要为了用而用）
2. **消息丢失**：MQ 可能因网络故障、Broker 宕机、消费端异常等原因导致消息丢失。
3. **消息重复**：消息可能被多次投递，需要业务端保证**幂等性**。
4. **消息顺序错乱**：MQ 可能因网络故障、Broker 宕机、消费端异常等原因导致消息丢失。
5. **死信**：消息多次消费失败后进入死信队列，需要额外处理。
6. **消息一致性**：在上述例子中，若库存系统写入成功，但物流系统写入失败，数据就不一致了。


# 四、消息协议

## （一）消息协议是什么

**MQ客户端和服务端之间，约定好的一套通信规则**：规定消息长什么样、怎么建立连接、怎么发消息、怎么收消息、出错怎么处理、怎么确认收到消息。

>底层依然是 TCP 传输字节流，但 TCP 只负责把字节传到对方；**消息协议定义这一串字节代表什么含义**。

## （二）常见的消息协议

### 1. AMQP（Advanced Message Queuing Protocol）

中文：**高级消息队列协议**，是一套开放的应用层**二进制消息协议**，专门用于消息中间件，**RabbitMQ 就是 AMQP 最经典的实现**

特点：
1. **跨语言、跨平台** ：只要客户端和 MQ 都遵守 AMQP 协议，不管是 Java/Python/Go，不同系统之间都可以收发消息。
2. **定义完整消息模型** 
3. **可靠消息投递**
