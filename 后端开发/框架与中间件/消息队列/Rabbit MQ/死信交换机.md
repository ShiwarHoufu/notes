# 一、死信

队列中的消息满足下列情况之一时，就会成为**死信（dead letter）**：

1. 消费者使用 `basic.reject` 或 `basic.nack` 声明消费失败，并且 requeue 参数为 false
2. 消息是**过期消息**：达到了队列或消息本身设置的过期时间（TTL），超时无人消费
3. 队列的**消息堆积满**了，最早的消息可能成为死信

# 二、死信交换机（DLX）

如果队列通过 `dead-letter-exchange` 属性指定了一个交换机，该队列中的死信就会投递到这个交换机中，这个交换机称为**死信交换机（Dead Letter Exchange，简称 DLX）**。

要点：
- DLX 是**配置在队列上**的属性（`dead-letter-exchange`），不是配置在消息上。
- 死信转投由 RabbitMQ 自动完成，业务代码不感知。
- 死信进入 DLX 后，照常走交换机的路由规则，由绑定到 DLX 的队列（如 `dlx.queue`）接手，交给另一个消费者处理。
