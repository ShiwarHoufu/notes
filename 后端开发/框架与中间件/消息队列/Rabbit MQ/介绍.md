
RabbitMQ 是开源的消息队列，基于 **AMQP** 协议，用来做异步消息通信。
>生产者、消费者基于 AMQP 协议，和 Broker 通信

# 一、工作原理
![[IMG_20261012_140754.jpg]]
## Producer 生产者

负责往 MQ 里发消息。
- **Connection（连接）**：和 RabbitMQ Broker 之间的 TCP 物理连接。TCP 连接开销大，一般一个客户端只建立少量 Connection。
- **Channel（通道）**：在一个 Connection 内部开辟的轻量级逻辑通道。


## Broker (RabbitMQ 服务本体)

1. **Virtual host（虚拟主机 vhost）**
可以理解成 RabbitMQ 里的命名空间 / 隔离环境。用来做**用户隔离、权限控制**。
一个 Broker 可以创建多个 vhost，不同 vhost 之间的交换机、队列完全隔离；

2. **Exchange 交换机**
生产者不会直接把消息发到队列，消息先发给交换机。 
交换机路由规则**把消息转发到队列**。 
>常见交换机类型：direct、fanout、topic、headers。

3. **Binding 绑定**
**Exchange 和 Queue 之间的关联关系**。 
绑定可以带上 `routingKey`，交换机就是通过 binding 的路由键，判断消息投递到哪个队列。

4. **Queue 队列**
真正**存储消息**的容器，消息最终落到队列，等待消费者来取。

## Consumer 消费者

**负责监听并消费队列里的消息。**
- 和生产者一样：先建立 `Connection`，在连接上开启多个 `Channel`；
- Channel 订阅队列，一旦队列有消息，推送给消费者。

# 二、交换机类型
## Direct（直连交换机）

- 路由规则：**精确匹配 routingKey**
- 绑定：队列绑定交换机时指定 `bindingKey`；消息携带 `routingKey`，两者完全相等才投递。
- 场景：单播。例如：错误日志单独投递到异常告警队列。
![[IMG_20261012_164452.jpg|430]]
## Fanout（扇出交换机）

- 路由规则：**忽略 routingKey，广播给所有绑定的队列**
- 特点：最简单，性能最高。
- 场景：广播。例如：实时通知、直播间消息、多服务同步缓存。
![[IMG_20261012_164532.jpg|420]]
## Topic（主题交换机）

- 路由规则：**模糊匹配 routingKey**，用 `.` 分隔，支持通配符
    - `*`：匹配 1 个
    - `#`：匹配 0 个或多个
- 场景：日志分类、多维度消息订阅，最常用。
- 示例 routingKey ：
1. `key1.key2.key3.key4`:  下图四个队列都可以匹配。
2. `key1` : 只会匹配 `key1.#`
![[IMG_20261012_164551.jpg|428]]

## Headers（头交换机）
>性能差，很少使用。

- 路由规则：**不看 routingKey，看消息 headers 头部键值对匹配**
- 绑定队列时设置 `arguments`，有两种匹配模式：
    - `x-match=all`：所有 header 键值都要匹配
    - `x-match=any`：任意一个 header 匹配即可
- 场景：复杂多条件路由，业务极少用到。
![[IMG_20261012_164649.jpg|456]]

# 三、工作模式
| 模型                | 结构                                    | 特点                |
| ----------------- | ------------------------------------- | ----------------- |
| Simple            | 1 生产者 → 1 队列 → 1 消费者                  | 点对点               |
| Work              | 1 生产者 → 1 队列 → N 消费者                  | 竞争消费              |
| Publish/Subscribe | Fanout 交换机 → N 队列 → N 消费者             | 广播                |
| Routing           | Direct 交换机按 routingKey 精确路由           | 按 key 分发          |
| Topics            | Topic 交换机按通配符路由                       | `order.*.paid` 之类 |
| RPC               | 请求/回复队列 + `reply_to`/`correlation_id` | 同步调用              |

# 四、基本代码操作

前置依赖：
```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-amqp</artifactId>
</dependency>
```

## 声明队列和交换机

### 方式 1：@Configuration + @Bean
> 推荐，集中管理
```java
@Configuration
public class RabbitConfig {
    // 1. 常量
    ...

    // 声明队列
    @Bean
    public Queue directQueue() {
        return new Queue(DIRECT_QUEUE, true);
    }
    // 声明 Direct 交换机
    @Bean
    public DirectExchange directExchange() {
        // name, durable, autoDelete
        return new DirectExchange(DIRECT_EXCHANGE, true, false);
    }
    // 绑定：队列 + 交换机 + routingKey
    @Bean
    public Binding directBinding(Queue directQueue, DirectExchange directExchange){
        return BindingBuilder
                .bind(directQueue)
                .to(directExchange)
                .with(ROUTING_KEY);
    }
```


### 方式 2：@RabbitListener 注解内声明
> 适合简单场景
```java
@Component
public class RabbitConsumer {

    @RabbitListener(bindings = @QueueBinding(
            value = @Queue(value = " ", durable = "true"),
            exchange = @Exchange(value = " ", type = "direct", durable = "true"),
            key = " "
    ))
    
    public void listen(String msg) {
        System.out.println("收到消息：" + msg);
    }
}
```
