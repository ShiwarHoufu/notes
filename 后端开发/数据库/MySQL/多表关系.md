
表与表之间的关系共三种：**一对多、一对一、多对多**。

| 关系 | 场景举例 | 实现方式 |
| --- | --- | --- |
| **一对多** | 用户—订单、部门—员工 | 在**多**的一方（从表）加外键，指向**一**的一方（主表）的主键 |
| **一对一** | 用户—身份证信息 | 在**任意一方**加外键，并设置外键为**唯一（UNIQUE）** |
| **多对多** | 学生—课程 | 建立**第三张中间表**，至少包含两个外键，分别关联两方的主键 |

## 1. 一对多

**场景**：一个用户可以有多个订单，一个订单只能属于一个用户。

**实现**：
- 在「多」的一方（**从表**）添加外键字段，指向「一」的一方（**主表**）的主键
- 在从表的外键字段上**建立索引**，提升关联查询效率

> 这两步对应的是推荐的**逻辑外键**做法。注意第 1 步是加「外键**字段**」而非「外键**约束**」——没有 `FOREIGN KEY`约束就不会有自动索引，所以第 2 步必须自己写

```sql
-- 主表：部门
CREATE TABLE tb_dept (
    id   INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(20)
);

-- 从表：员工，dept_id 指向部门主键，并在该字段上建索引
CREATE TABLE tb_emp (
    id      INT PRIMARY KEY AUTO_INCREMENT,
    name    VARCHAR(20),
    dept_id INT,
    INDEX idx_dept_id (dept_id)
);
```

## 2. 一对一

**场景**：用户与身份证信息，一个用户对应一份身份证信息。

> 一对一关系多用于**单表拆分**：将一张表的基础字段放在一张表中，其他字段放在另一张表中，以提升操作效率。

**实现**：在**任意一方**加入外键，关联另外一方的主键，并且设置外键为**唯一的（UNIQUE）**。

```sql
CREATE TABLE tb_user_card (
    id      INT PRIMARY KEY AUTO_INCREMENT,
    user_id INT UNIQUE,        -- UNIQUE 约束保证一个用户只对应一条记录
    card_no VARCHAR(18)
);
```

## 3. 多对多

**场景**：学生与课程，一个学生可以选修多门课程，一门课程也可以供多个学生选择。

**实现**：建立**第三张中间表**，中间表至少包含两个外键，分别关联两方的主键。

> 例：`tb_student` 与 `tb_course`，中间表 `tb_student_course` 中放 `studentid`、`courseid` 两个外键。

```sql
CREATE TABLE tb_student_course (
    id        INT PRIMARY KEY AUTO_INCREMENT,
    studentid INT,             -- 关联 tb_student 主键
    courseid  INT              -- 关联 tb_course 主键
);
```

## 4. 外键的两种实现

三种关系都靠**外键**落地，具体有两种做法：

**物理外键**：使用 `FOREIGN KEY` 约束实现的外键关系。

**逻辑外键（推荐）**：在应用层实现的外键关系——从表添加关联字段，**不建立 `FOREIGN KEY` 约束**，由业务代码保证数据一致性，并在关联字段上建立索引，提升关联查询效率。

| 对比项   | 物理外键                  | 逻辑外键      |
| ----- | --------------------- | --------- |
| 一致性保证 | 数据库层面强约束              | 由业务代码保证   |
| 性能    | 影响增删改性能（需要校验约束）       | 无额外校验开销   |
| 适用场景  | 仅适用单节点数据库，不适用分布式、集群场景 | 便于分库分表和扩展 |
| 风险    | 容易引发数据库锁死问题，影响性能      | 依赖业务代码质量  |
