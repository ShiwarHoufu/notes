
# 一、概述

索引（index）是帮助 MySQL **高效获取数据**的有序**数据结构**。

本质是一笔用空间和写入性能换读取性能的交易：**索引越多，写入越慢、占用空间越大。**

| 优势                                | 劣势                                                               |
| --------------------------------- | ---------------------------------------------------------------- |
| 提高数据检索效率，降低数据库的 **IO 成本**         | 索引列本身要**占用空间**                                                   |
| 通过索引列对数据排序，降低数据排序成本，降低 **CPU 消耗** | 提高查询效率的同时也**降低更新表的速度**，对表执行 `INSERT` / `UPDATE` / `DELETE` 时效率降低 |

可选的数据结构有二叉树、红黑树、B-Tree、B+Tree 等多种，MySQL 实际选用的是 **B+Tree**。

# 二、索引结构

MySQL 的索引在**存储引擎层**实现，不同存储引擎支持不同的索引结构：

| 索引结构                | 描述                                   |
| ------------------- | ------------------------------------ |
| **B+Tree 索引**       | 最常见的索引类型，大部分引擎都支持                    |
| **Hash 索引**         | 底层用哈希表实现，只有精确匹配索引列的查询才有效，不支持范围查询     |
| **R-tree（空间索引）**    | MyISAM 引擎的特殊索引类型，主要用于地理空间数据类型，通常使用较少 |
| **Full-text（全文索引）** | 通过建立倒排索引快速匹配文档，类似 Lucene、Solr、ES     |
MySQL 对经典的B+Tree进行了优化。增加了一个指向相邻叶子点的链表指针，形成带有顺序指针的B+Tree，提高区间访问性能。
