Redis （Remote Dictionary Server），远程字典服务。
是基于内存的键-值对数据库，读写速度极快。

# 一、Redis 为什么这么快

>这里只是简单了解，后续再进行深入学习

1. **纯内存操作**（根本原因） 

| 对比项       | 磁盘读取（硬盘 SSD/HDD）                             | 内存读取（RAM）           |
| --------- | -------------------------------------------- | ------------------- |
| **读写速度**  | 慢。HDD：约 50–200MB/s；SSD：300–7000MB/s；毫秒级 (ms) | 极快。几十 GB/s，纳秒级 (ns) |
| **存储性质**  | 持久化存储，断电后数据保留                                | 易失，断电数据全部丢失         |
| **容量**    | 容量大，常见 512GB~20TB                            | 容量小，常见 8GB~128GB    |
| **IO 开销** | 涉及磁盘控制器、磁头 / 闪存单元、操作系统 IO 栈，CPU 开销大          | CPU 直接通过总线访问，系统开销低  |
| **典型用途**  | 长期保存文件、数据库数据                                 | 缓存热点数据，存放当前正在使用的数据  |

2. **单线程执行命令，避免锁和上下文切换**  
>Redis 并不是所有事情都单线程。持久化、异步删除、AOF 刷盘等有后台线程；Redis 6.0 后还引入了多线程 IO，但**命令执行仍然是单线程**，多线程只分担网络读写和协议解析。
 
3. **高效的数据结构**  
 - Redis 没有直接套用普通链表、哈希表，而是做了大量优化
4. **IO 多路复用**
5. **渐进式 rehash**  
6. **简单的网络协议 RESP**  
7. **内存分配器 jemalloc**  
8. **持久化尽量不阻塞主流程**  
9. **多线程 IO 的补充**
