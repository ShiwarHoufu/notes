**NoSQL（Not Only SQL）泛指非关系型数据库**，和 MySQL、Oracle 这类传统关系型数据库对应。它不用固定表、行、列的关系模型，适合存储**海量、结构多变、高并发读写**的数据。

# 一、核心特点

1. **无固定 Schema**：不需要提前定义字段，同一份集合里的数据字段可以不一样，新增属性不用改表结构。
2. **水平扩展（横向扩容）**：扛不住压力时，加更多服务器节点，而不是升级单台机器配置，适合互联网海量流量。
3. **大多是最终一致性（BASE）**： 不像 MySQL 严格 ACID 事务，优先保证可用性，数据短暂不一致，最后会同步一致。（部分 NoSQL 也支持事务）
4. **没有表关联 join** ：不擅长多表复杂联表查询。

# 二、主流分类

| 类型               | 说明                | 代表产品            | 典型场景              |
| ---------------- | ----------------- | --------------- | ----------------- |
| 键值数据库 Key-Value  | 键 + 值             | Redis           | 缓存、购物车、排行榜、会话     |
| 文档数据库 Document   | 存储 JSON/BSON 文档   | MongoDB         | 用户资料、商品信息、内容管理    |
| 宽列存储 Wide-Column | 按列簇存储，类似大表但每行字段可变 | HBase、Cassandra | 大数据、物联网、时序、日志     |
| 图数据库 Graph       | 存顶点 + 边，专门表达关系    | Neo4j           | 社交关系、推荐、知识图谱、风控链路 |

>NoSQL 不是不能写 SQL，名字 “Not Only SQL” 意思是不止可以用 SQL，还有别的查询方式；很多 NoSQL 产品也支持**类SQL** 查询。
